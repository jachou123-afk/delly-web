讀取或修改文件不代表已授權發送 LINE。執行者必須依使用者本次指定的批次、聊天室及範圍操作，並遵守當下工具的安全規則。


商品圖庫原圖與 LINE 發送圖片分開計數：圖庫每款最多 10 張，LINE 每款仍最多 5 張。原圖維持原始位元組、SHA-256、格式／像素／大小與商品版本核對；補圖不改價格或雲表主圖。

NAS 連線檢查只顯示通過格式檢查的 HTTPS origin 與轉向目的 origin，不顯示帳密、路徑或查詢參數。遇到重新導向仍立即停止，不跟隨、不傳送帳密；先確認同一 NAS 與正確入口，再更正設定及驗證新連線。顯示安全診斷不代表 NAS 登入、商品原圖保存或綁定成功。

批次 NAS 原圖補存入口預設關閉，只接收已核對的實際分頁／NO、有序 SHA-256 與對應原始圖片 ZIP，不接受聊天、價格或任意路徑。每次最多順序處理 10 款，沿用正式單款來源與公式防呆；每款成功後保留新 NAS 連線原圖讀回收據，失敗隔離且不自動重試或切換上傳方式。既有原圖核對模式不呼叫上傳 API，已完成款續跑不重做。

單款補圖另有唯讀原圖檢查：僅查已選原圖的 NAS 檔案資訊，或依現有綁定順序讀回、展示及下載原始位元組。只有 File Station API 408 判為不存在；HTTP 408／502、權限或讀取錯誤均不當缺檔，大小相同也不代表 SHA-256 完成。檢查不保存、不替換、不追加圖片；來源、公式或綁定版本變更即停止。

完整既有 NAS 索引與綁定的同一圖組採純唯讀核對，保留前後來源、公式、綁定版本、位置索引與原始位元組檢查，不重新發布索引或綁定。批次處理的 Google Sheets GET 在送出前使用同服務程序共用的 45 次／60 秒節奏；單次讀取最多等待 120 秒，達上限或服務回報 429 即停止該段並保留後續待處理，不新增任何 API 寫入重試。其他程序或手動讀取不在此節奏範圍，仍以服務實際回應為準。

NAS getinfo 的逐檔缺檔回應只接受單筆精確 `{path, code:408}`，路徑必須完全等於本次原圖；多欄位、矛盾、其他代碼或 HTTP 408／502 均不視為缺檔。缺檔查核本身不會上傳，必須明確執行已授權的原圖補存。
